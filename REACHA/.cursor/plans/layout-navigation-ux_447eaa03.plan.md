# サイドバー・ヘッダー・フッター追加によるナビゲーション強化プラン

### 1. 現状ページ構成の前提整理

- **トップ〜会社別ページ**
- 会社一覧 or 会社名入力ページ（`/company` 系）から、`/company/[company]`（リサーチ結果タブ＋提案作成ボタン）へ遷移。
- 提案作成後は `/company/[company]/proposal` で JSON 提案とキーワードネットワークを閲覧・比較できる構造になっている。
- **バックグラウンド実行フロー**
- リサーチ実行／提案作成は FastAPI 側でバックグラウンド実行され、フロントはポーリングで進捗確認しているため、**ページ間を行き来しても処理自体は継続**する。

### 2. グローバルレイアウト（サイドバー＋ヘッダー＋フッター）の設計

- **サイドバー（左固定）**
- 常に表示されるナビとして、主に以下を配置:
    - 「ホーム / 新規リサーチ」リンク（会社入力ページへ）
    - 「最近の会社」セクション（直近アクセスした 3〜5 社の `/company/[company]` へのショートカット）
    - 「実行中のジョブ」インジケータ（あれば1件だけ表示、クリックで該当会社ページへ）
- モバイル／狭い画面ではハンバーガーメニュー風に折りたたみ。
- **ヘッダー（上部バー）**
- 右上に以下のような軽量情報を表示:
    - 現在表示中の会社名＋ページ種別（リサーチ結果／提案）
    - ジョブ状態バッジ：`idle / running / completed`（`/api/run/status` と `/api/proposal/{company}/progress` の結果を統合表示）。
- **フッター**
- シンプルに利用上の注意（長時間実行・バックグラウンド継続など）とバージョン情報を表示。

### 3. ジョブ状態とナビゲーションの連携

- **実行中会社へのクイックアクセス**
- サイドバーの「実行中のジョブ」セクションで、現在 `status === running` な company があれば、その会社名＋種別（リサーチ / 提案作成）を表示し、クリックで対応ページへジャンプ。
- **完了時のソフトな通知と導線**
- リサーチ完了: `/company/[company] `ページで `/api/run/status` の `status` が `running` → `idle` に変わった瞬間に、ページ上部に「リサーチが完了しました。結果を見る」トースト（ボタン付き）を表示。
- 提案作成完了: `/company/[company]` 上にいる場合はトーストから `/company/[company]/proposal` へワンクリック遷移できるようにする（自動リダイレクトまではしない）。

### 4. ページごとの使い勝手改善（最小機能で）

- **会社入力／一覧ページ**
- 最近アクセスした会社一覧と「提案まで完了済 / リサーチのみ / 実行中」などのステータスアイコンを併記し、クリックで該当会社のページに遷移できるようにする（API は既存の `/api/companies` ＋ `/api/results/{company}` を再利用）。
- **会社別リサーチページ `/company/[company]`**
- 上部に、サイドバーと同じ「ジョブ状態バッジ」と、提案作成ページへの明示的なボタン（すでに存在するもの）を配置。
- バックエンド実行中に他ページへ移っても、サイドバー経由で簡単に戻れるようにする。
- **提案ページ `/company/[company]/proposal`**
- ヘッダーに「← {company} のリサーチ結果に戻る」リンクを常設し、ワンクリックでリサーチタブに戻れるようにする（既存の戻るボタンは維持しつつ、位置を整理）。

### 5. 実装の進め方と影響範囲

- **レイアウトコンポーネントの導入**
- `flont/app/layout.tsx` または共通レイアウトコンポーネントを新設し、サイドバー／ヘッダー／フッターをここにまとめる。
- 既存ページはこのレイアウトでラップするだけに留め、個別ロジックや API 呼び出しは極力変えない。
- **状態取得の統一フック**
- `lib` 配下に簡単なカスタムフック（例: `useJobStatus`）を作り、サイドバーと各ページで同じロジックを使って `/api/run/status` や `/api/proposal/{company}/progress` を参照するようにして、重複を抑える。
- **既存機能は増やさず、導線だけ追加**
- 新しい API は作らず、基本的に既存の `/api/companies` `/api/results/{company}` `/api/run/status` `/api/proposal/{company}/progress` を使って情報を集約・表示する方針とする。
