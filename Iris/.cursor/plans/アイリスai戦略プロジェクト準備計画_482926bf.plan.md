# アイリスオーヤマ AI戦略プロジェクト 技術検証・調査計画

## 1. タスク設計（優先度・工数・内容）

### 1.1 技術検証タスク（実証可能なもの）

#### タスク1-1: Microsoft Copilot機能検証（特にVBAマクロ連携）

- **優先度**: 高
- **工数**: 3-4日
- **内容**:
- Copilot for Microsoft 365の主要機能リストアップ
- VBAマクロとの連携可能性の検証
    - Excel CopilotとVBAマクロの共存・連携方法
    - VBAコード生成・修正支援機能の検証
    - 既存VBAマクロ資産の活用方針
- 実証環境での動作確認（可能な範囲）
- 制約事項・注意点の整理

#### タスク1-2: Microsoft Copilot Dashboard機能調査

- **優先度**: 高
- **工数**: 2-3日
- **内容**:
- Dashboardで取得可能な指標・メトリクスの洗い出し
- 利用状況モニタリング機能の確認
- KPI設定に活用できるデータ項目の整理
- ダッシュボード画面のスクリーンショット取得（可能な範囲）
- レポート出力機能の確認

#### タスク1-3: Copilotセキュリティ検証

- **優先度**: 高
- **工数**: 3-4日
- **内容**:
- データ処理フロー（入力→処理→出力）の調査
- 機密情報の取り扱いポリシー確認
    - Microsoft公式ドキュメントの精査
    - データ保持・学習利用の有無
    - テナント分離・データリージョンの確認
- セキュリティベストプラクティスの整理
- リスク評価と対策案の提示

### 1.2 調査・分析タスク

#### タスク2-1: 中央組織と事業部の役割分担調査

- **優先度**: 中
- **工数**: 4-5日
- **内容**:
- 他社事例の収集・分析
    - CoE（Center of Excellence）モデルの事例
    - 中央集権型 vs 分散型の比較
    - 事業部単位（5-10名規模）の推進体制事例
- 役割分担のフレームワーク作成
    - 中央組織の役割（戦略・ガバナンス・技術支援）
    - 事業部の役割（実装・ユースケース発掘・推進）
- コミュニケーション・連携体制の設計案

#### タスク2-2: 事務局リソース（ヒト）要件調査

- **優先度**: 中
- **工数**: 2-3日
- **内容**:
- 他社事例での事務局体制（人数・スキルセット）
- 必要な役割・スキルの整理
    - プロジェクトマネージャー
    - 技術リーダー/アーキテクト
    - チェンジマネジメント担当
    - データガバナンス担当
- リソース確保の推奨案

### 1.3 提案資料作成タスク

#### タスク3-1: 技術検証結果まとめ

- **優先度**: 高
- **工数**: 2-3日
- **内容**:
- 検証結果のドキュメント化
- 機能マトリクス・比較表の作成
- 推奨ユースケースの整理（既存のmemo02.mdの活用）
- 技術的制約・注意事項の明記

#### タスク3-2: 活用方針提案資料作成

- **優先度**: 高
- **工数**: 3-4日
- **内容**:
- 「どこで・何を・どう使うべきか」の示唆
- ロードマップ案（フェーズ別）
- ツール選定の推奨（Copilot for M365、Copilot Studio、Azure AI等）
- 導入優先順位の提案
- 期待効果の試算（既存事例ベース）

### フェーズ1: 技術検証（Week 1-2）

- **Day 1-2**: Copilot機能調査開始
- Microsoft公式ドキュメントの精査
- VBAマクロ連携に関する技術情報収集
- 実証環境準備（可能な範囲）
- **Day 1-2**: Dashboard機能調査開始
- Microsoft Copilot Dashboardの機能一覧確認
- モニタリング指標の洗い出し
- **Day 1-3**: セキュリティ調査開始
- Microsoft Trust Center等の公式情報確認
- データ処理フローの理解

#### Week 2: 検証の深掘りと並行して他社事例調査開始

- **Day 4-5**: Copilot機能検証の深掘り
- VBA連携の具体的な検証（実証可能な範囲）
- 機能制約の整理
- **Day 3-4**: Dashboard機能の詳細確認
- レポート機能・エクスポート機能の確認
- **Day 4-5**: セキュリティ検証のまとめ

- 他社事例の収集（Web調査、公開資料）

### フェーズ2: 調査の集約と分析（Week 3）

#### Week 3: 調査結果の分析と提案資料の骨子作成

- **Day 1-2**: 役割分担調査の継続・分析
- 事例のパターン分析
- フレームワーク作成
- **Day 2-3**: 事務局リソース調査
- 他社事例の収集・分析
- リソース要件の整理
- **Day 3-5**: 技術検証結果のまとめ
- 各検証タスクの結果をドキュメント化
- 機能マトリクス・比較表の作成

### フェーズ3: 提案資料作成（Week 4）

#### Week 4: 活用方針提案資料の作成

- **Day 1-2**: 活用方針の設計
- ユースケースとツールのマッピング
- ロードマップ案の作成
- 導入優先順位の検討
- **Day 3-4**: 提案資料の作成
- 技術検証結果の統合
- 調査結果の統合
- 示唆・推奨事項の明確化

- 資料の最終確認
