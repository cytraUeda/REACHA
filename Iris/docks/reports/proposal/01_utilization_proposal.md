# Microsoft Copilot活用方針提案資料

## 1. エグゼクティブサマリー

### 1.1 提案の目的
本資料は、アイリスオーヤマにおけるMicrosoft Copilot for Microsoft 365の活用方針を提案するものです。技術検証・調査結果を基に、「どこで・何を・どう使うべきか」を示唆し、段階的な導入ロードマップを提示します。

### 1.2 主要な示唆
1. **初期段階**: メール・会議・文書作成中心のユースケースから開始
2. **発展段階**: SharePoint等の情報資産を活用した高度なユースケースへ展開
3. **組織体制**: ハイブリッド型モデル（CoEモデル）の採用を推奨
4. **VBAマクロ**: 既存資産は維持しつつ、段階的な移行を検討

---

## 2. 技術検証結果の要約

### 2.1 機能検証結果
- **主要機能**: Outlook、Word、Excel、PowerPoint、Teams、SharePointで多様な機能を提供
- **VBAマクロ連携**: 直接実行は不可だが、共存・間接連携は可能
- **推奨アプローチ**: 既存VBAマクロ資産を維持しつつ、新規業務からCopilotを活用

### 2.2 Dashboard機能
- **利用状況メトリクス**: アクティブユーザー数、利用頻度、アプリケーション別利用状況等を取得可能
- **KPI設定**: 採用率、利用深度、継続利用率等のKPI設定に活用可能
- **モニタリング**: 定期的なレビュー・分析により、効果測定が可能

### 2.3 セキュリティ評価
- **基本的な安全性**: Microsoft 365環境内データはCommercial Data Protectionにより保護
- **機密情報**: Microsoft 365環境内データであれば、基本的に機密情報を入力しても問題ない
- **対策**: 適切なセキュリティ設定、DLPポリシー、ユーザー教育が重要

## 3. どこで・何を・どう使うべきか

### 3.1 ツール・AI活用マップ

#### 3.1.1 初期段階（導入後0-6ヶ月）

| 業務領域 | ツール | 活用内容 | 期待効果 | 優先度 |
|---|---|---|---|---|
| **メール業務** | Outlook Copilot | メール要約、メール作成支援、メール返信提案 | 週12-30分の時間削減 | 高 |
| **会議業務** | Teams Copilot | 会議要約、議事録生成、会議前準備 | 議事録作成時間の削減 | 高 |
| **文書作成** | Word Copilot | 文書ドラフト作成、文書要約、文書編集支援 | 1日24分の時間削減、完了時間0.5-1日短縮 | 高 |
| **プレゼン作成** | PowerPoint Copilot | プレゼン作成、デザイン提案、Word→PowerPoint変換 | 1日19分の時間削減 | 高 |
| **データ分析** | Excel Copilot | データ分析支援、数式生成、データ可視化 | データ分析時間の削減 | 中 |

#### 3.1.2 発展段階（導入後6-12ヶ月）

| 業務領域 | ツール | 活用内容 | 期待効果 | 優先度 |
|---|---|---|---|---|
| **情報検索** | SharePoint Copilot | SharePoint横断検索、規程・手順書検索 | 手作業検索の削減 | 高 |
| **部門特化業務** | Copilot Studio | 部門特化AIエージェント、FAQ検索 | 部門固有の業務効率化 | 中 |
| **自動化** | Azure AI + Copilot Studio | 文書処理の自動化、顧客フィードバック分類 | 業務プロセスの自動化 | 低 |

### 3.2 ツール選定の推奨

#### 3.2.1 必須ツール
- **Microsoft Copilot for Microsoft 365**: 全社的なAI民主化の基盤
  - 対象: 全社員（段階的展開）
  - 用途: メール、会議、文書作成、データ分析

#### 3.2.2 推奨ツール（発展段階）
- **Copilot Studio**: 部門特化AIエージェントの構築
  - 対象: 特定部門・業務
  - 用途: 規程検索、FAQ検索、部門特化業務支援
- **Azure AI Services**: 高度なAI機能の実装
  - 対象: 特定の業務プロセス
  - 用途: 文書処理の自動化、データ分類

### 3.3 導入優先順位

#### 3.3.1 Phase 1: 基盤構築（導入前-導入後3ヶ月）
1. **Microsoft Copilot for Microsoft 365**: 全社的な基盤ツールとして導入
2. **優先ユースケース**: メール要約、会議要約、文書作成、プレゼン作成

#### 3.3.2 Phase 2: 拡大（導入後3-6ヶ月）
1. **ユースケースの拡大**: Excel分析、メール横断検索
2. **部門別展開**: 事業部ごとの推進

#### 3.3.3 Phase 3: 高度化（導入後6-12ヶ月）
1. **Copilot Studio**: 部門特化AIエージェントの構築
2. **SharePoint横断検索**: 情報資産の活用
3. **Azure AI Services**: 高度なAI機能の実装（必要に応じて）

## 5. 組織体制・役割分担

### 5.1 推奨組織構造
- **ハイブリッド型モデル（CoEモデル）**: 中央組織（CoE）と事業部の協働
- **中央組織（CoE）**: 6-10名（戦略、技術、チェンジマネジメント、データガバナンス、プロジェクトマネジメント）
- **事業部**: 各事業部にAI推進リーダー1名（5-10名規模の事業部）

### 5.2 役割分担
- **中央組織（CoE）**: 戦略・ガバナンス・技術支援・標準化
- **事業部**: 実装・ユースケース発掘・推進・成功事例創出

### 5.3 コミュニケーション体制
- **定例会議**: 中央組織と事業部AI推進リーダーの月次定例会
- **コミュニティ**: 全社的なAI活用コミュニティ（Teams等）
- **情報共有**: SharePoint等での情報共有プラットフォーム

## 7. リスク・対策

### 7.1 主要リスク

| リスク | 影響度 | 対策 |
|---|---|---|
| **採用率の低さ** | 高 | チェンジマネジメント、トレーニング、成功事例共有 |
| **セキュリティリスク** | 高 | 適切な設定、DLPポリシー、ユーザー教育 |
| **VBAマクロ資産との競合** | 中 | 役割分担の明確化、段階的移行 |
| **リソース不足** | 中 | 段階的なリソース確保、外部リソースの活用 |
| **技術的な課題** | 中 | 技術アーキテクトによる支援、ベンダーサポート |

### 7.2 対策の優先順位
1. **セキュリティ対策**: 導入前の設定確認・最適化
2. **チェンジマネジメント**: 全社的な推進、トレーニング
3. **技術支援**: 事業部への技術的支援
4. **継続的な改善**: 定期的なレビュー・改善

## 9. 結論・推奨事項

### 9.1 主要な示唆

1. **段階的な導入が効果的**
   - 初期段階: メール・会議・文書作成中心
   - 発展段階: SharePoint等の情報資産活用

2. **組織体制の構築が重要**
   - ハイブリッド型モデル（CoEモデル）の採用
   - 中央組織と事業部の協働

3. **VBAマクロ資産の活用**
   - 既存資産は維持しつつ、段階的な移行を検討
   - 役割分担の明確化

4. **セキュリティ対策の徹底**
   - 適切な設定、DLPポリシー、ユーザー教育

### 9.2 アイリスオーヤマへの推奨事項

#### 9.2.1 最優先事項
1. **組織体制の構築**: 中央組織（CoE）の設置、事業部AI推進リーダーの任命
2. **セキュリティ対策**: セキュリティ設定の確認・最適化、DLPポリシーの設定
3. **Pilot導入**: 特定部門・ユーザーでのPilot導入、優先ユースケースの展開

#### 9.2.2 次優先事項
1. **全社展開**: 段階的な全社展開、ユースケースの拡大
2. **成功事例の創出**: 事業部ごとの成功事例創出、横展開
3. **高度化**: Copilot Studioの検討、SharePoint横断検索の展開

#### 9.2.3 継続的な改善
1. **KPI管理**: 定期的なKPI評価、改善施策の実施
2. **ユーザー教育**: 継続的なトレーニング、ベストプラクティスの共有
3. **技術支援**: 事業部への技術的支援、課題解決
