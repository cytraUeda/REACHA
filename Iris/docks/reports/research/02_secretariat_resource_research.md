# 事務局リソース（ヒト）要件調査レポート

## 1. 調査概要

### 1.1 調査目的
- 事務局に必要なリソース（ヒト）について他社事例を調査
- 必要な役割・スキルセットの整理
- リソース確保の推奨案の提示

### 1.2 調査日
2024年12月

### 1.3 調査方法
- 他社事例の収集（公開資料、業界レポート）
- 役割・スキル要件の分析
- リソース確保方法の整理

## 2. 他社事例での事務局体制

### 2.1 事例A: 製造業大手（従業員数: 10,000名超）

#### 2.1.1 事務局体制
- **総人数**: 10名
- **構成**:
  - AI戦略担当: 2名（マネージャー1名、アナリスト1名）
  - 技術アーキテクト: 3名（シニア1名、ミドル2名）
  - チェンジマネジメント: 2名（マネージャー1名、スペシャリスト1名）
  - データガバナンス: 2名（マネージャー1名、スペシャリスト1名）
  - プロジェクトマネージャー: 1名

#### 2.1.2 各役割の詳細
- **AI戦略担当**:
  - 役割: AI戦略の策定、ロードマップの作成、経営層への報告
  - スキル: 戦略思考、ビジネス理解、プレゼンテーション能力
- **技術アーキテクト**:
  - 役割: 技術標準の確立、技術支援、ベンダー管理
  - スキル: AI技術、Microsoft 365、クラウド技術、アーキテクチャ設計
- **チェンジマネジメント**:
  - 役割: 全社的な推進、トレーニング、コミュニティ運営
  - スキル: チェンジマネジメント、トレーニング、コミュニケーション能力
- **データガバナンス**:
  - 役割: データポリシー、セキュリティポリシー、コンプライアンス
  - スキル: データガバナンス、セキュリティ、コンプライアンス
- **プロジェクトマネージャー**:
  - 役割: プロジェクト管理、進捗管理、課題管理
  - スキル: プロジェクトマネジメント、進捗管理、課題解決

## 3. 必要な役割・スキルセット

### 3.1 AI戦略担当

#### 3.1.1 役割
- AI戦略の策定・推進
- ロードマップの作成・管理
- 経営層への報告・意思決定支援
- 全社的なKPI管理・モニタリング
- ベンダー管理（戦略面）

#### 3.1.2 必要なスキル
- **必須スキル**:
  - 戦略思考・ビジネス理解
  - AI・生成AIの基本的な理解
  - プレゼンテーション能力
  - プロジェクトマネジメントの基礎
- **推奨スキル**:
  - データ分析能力
  - 業界知識
  - 経営層とのコミュニケーション能力

#### 3.1.3 推奨人数
- **初期**: 1-2名（マネージャー1名、必要に応じてアナリスト1名）
- **拡大時**: 2-3名

### 3.2 技術アーキテクト

#### 3.2.1 役割
- 技術標準の確立・管理
- 技術アーキテクチャの設計
- 事業部への技術支援・相談対応
- ベンダー管理（技術面）
- 技術トレーニングの提供
- 技術的な課題解決

#### 3.2.2 必要なスキル
- **必須スキル**:
  - AI技術（生成AI、LLM等）の深い理解
  - Microsoft 365（特にCopilot）の技術的理解
  - クラウド技術（Azure等）の理解
  - アーキテクチャ設計能力
  - 技術的問題解決能力
- **推奨スキル**:
  - プログラミング能力
  - データエンジニアリング
  - セキュリティ技術

#### 3.2.3 推奨人数
- **初期**: 2-3名（シニア1名、ミドル1-2名）
- **拡大時**: 3-4名

### 3.3 チェンジマネジメント担当

#### 3.3.1 役割
- 全社的なAI民主化の推進
- トレーニングプログラムの企画・実施
- コミュニティ運営
- 成功事例の収集・共有・横展開
- ユーザーサポート
- 利用促進活動

#### 3.3.2 必要なスキル
- **必須スキル**:
  - チェンジマネジメント
  - トレーニング・教育能力
  - コミュニケーション能力
  - ファシリテーション能力
  - AI・Copilotの基本的な理解
- **推奨スキル**:
  - イベント企画・運営能力
  - コンテンツ作成能力
  - ユーザーサポート経験

#### 3.3.3 推奨人数
- **初期**: 1-2名（マネージャー1名、必要に応じてスペシャリスト1名）
- **拡大時**: 2-3名

### 3.4 データガバナンス担当

#### 3.4.1 役割
- データポリシー・セキュリティポリシーの確立・管理
- コンプライアンス要件への対応
- データ品質管理
- セキュリティリスク評価・対策
- 監査・ログ管理

#### 3.4.2 必要なスキル
- **必須スキル**:
  - データガバナンス
  - セキュリティ（特にクラウドセキュリティ）
  - コンプライアンス（GDPR、個人情報保護法等）
  - リスク評価・管理
- **推奨スキル**:
  - 監査経験
  - データプライバシー
  - Microsoft 365セキュリティ

#### 3.4.3 推奨人数
- **初期**: 1名（マネージャー）
- **拡大時**: 1-2名

### 3.5 プロジェクトマネージャー

#### 3.5.1 役割
- プロジェクト全体の管理
- 進捗管理・報告
- 課題管理・解決
- リソース管理
- ステークホルダー管理
- ベンダー管理（プロジェクト面）

#### 3.5.2 必要なスキル
- **必須スキル**:
  - プロジェクトマネジメント
  - 進捗管理・報告能力
  - 課題解決能力
  - コミュニケーション能力
  - ステークホルダー管理
- **推奨スキル**:
  - AI・ITプロジェクトの経験
  - ベンダー管理経験
  - リスク管理

#### 3.5.3 推奨人数
- **初期**: 1名
- **拡大時**: 1-2名

### 3.6 トレーニング担当（オプション）

#### 3.6.1 役割
- トレーニングプログラムの企画・実施
- トレーニング資料の作成
- トレーニング効果の測定
- オンライントレーニングの運営

#### 3.6.2 必要なスキル
- **必須スキル**:
  - トレーニング・教育能力
  - コンテンツ作成能力
  - AI・Copilotの理解
- **推奨スキル**:
  - オンライントレーニングの経験
  - 学習管理システム（LMS）の経験

#### 3.6.3 推奨人数
- **初期**: 0-1名（チェンジマネジメント担当が兼務可能）
- **拡大時**: 1名（専任）

## 4. リソース確保の推奨案

### 4.1 初期段階（導入前〜導入後3ヶ月）

#### 4.1.1 推奨体制
- **総人数**: 6名
- **構成**:
  - AI戦略担当: 1名（マネージャー）
  - 技術アーキテクト: 2名（シニア1名、ミドル1名）
  - チェンジマネジメント: 1名（マネージャー）
  - データガバナンス: 1名（マネージャー）
  - プロジェクトマネージャー: 1名

#### 4.1.2 確保方法
- **内部リソース**: 既存社員からの選出・異動
- **外部リソース**: 必要に応じて外部コンサルタント・専門家の活用
- **ハイブリッド**: 内部リソース + 外部サポート

### 4.2 成長段階（導入後3-6ヶ月）

#### 4.2.1 推奨体制
- **総人数**: 8名
- **構成**:
  - AI戦略担当: 1-2名（マネージャー1名、必要に応じてアナリスト1名）
  - 技術アーキテクト: 2-3名（シニア1名、ミドル1-2名）
  - チェンジマネジメント: 2名（マネージャー1名、スペシャリスト1名）
  - データガバナンス: 1名（マネージャー）
  - プロジェクトマネージャー: 1名

#### 4.2.2 拡大方法
- 初期段階の成果を踏まえた拡大
- 必要に応じて追加リソースの確保

### 4.3 成熟段階（導入後6-12ヶ月）

#### 4.3.1 推奨体制
- **総人数**: 10名
- **構成**:
  - AI戦略担当: 2名（マネージャー1名、アナリスト1名）
  - 技術アーキテクト: 3名（シニア1名、ミドル2名）
  - チェンジマネジメント: 2名（マネージャー1名、スペシャリスト1名）
  - データガバナンス: 2名（マネージャー1名、スペシャリスト1名）

- 業務量・成果に基づいた最適化
- 継続的な改善

## 5. リソース確保の方法

### 5.1 内部リソースの活用

#### 5.1.1 既存社員からの選出
- **メリット**:
  - 組織文化・業務への理解が深い
  - 既存のネットワークを活用できる
  - コストが比較的低い
- **デメリット**:
  - 必要なスキルが不足している可能性
  - 既存業務への影響
- **推奨アプローチ**:
  - 基本的なスキルを持つ社員を選出
  - トレーニング・教育を提供
  - 段階的な異動・兼務

#### 5.1.2 異動・兼務
- **メリット**:
  - 柔軟なリソース確保
  - 既存業務との連携
- **デメリット**:
  - リソースの分散
  - 専念できない可能性
- **推奨アプローチ**:
  - 初期段階では兼務も可
  - 成長段階で専任化を検討

### 5.2 外部リソースの活用

#### 5.2.1 外部コンサルタント
- **メリット**:
  - 専門的なスキル・経験
  - 迅速なリソース確保
  - 客観的な視点
- **デメリット**:
  - コストが高い
  - 組織文化への理解が浅い
- **推奨アプローチ**:
  - 特定の専門領域（技術アーキテクト、データガバナンス等）で活用
  - 内部リソースとのハイブリッド

#### 5.2.2 外部専門家
- **メリット**:
  - 深い専門知識
  - 最新の知見
- **デメリット**:
  - コストが高い
  - 継続的な関係構築が必要
- **推奨アプローチ**:
  - アドバイザリーとしての活用
  - 特定プロジェクトでの活用

### 5.3 ハイブリッドアプローチ（推奨）

#### 5.3.1 内部 + 外部の組み合わせ
- **内部リソース**: 戦略、チェンジマネジメント、プロジェクトマネジメント
- **外部リソース**: 技術アーキテクト、データガバナンス（初期段階）
- **メリット**:
  - コストとスキルのバランス
  - 組織文化と専門性の両立
  - 段階的な内部化

#### 5.3.2 段階的な内部化
- **Phase 1**: 外部リソース中心
- **Phase 2**: 内部 + 外部のハイブリッド
- **Phase 3**: 内部リソース中心（外部はアドバイザリー）

## 7. アイリスオーヤマへの推奨事項

### 7.1 初期段階の推奨体制

#### 7.1.1 推奨体制（6名）
- **AI戦略担当**: 1名（マネージャー）
- **技術アーキテクト**: 2名（シニア1名、ミドル1名）
- **チェンジマネジメント**: 1名（マネージャー）
- **データガバナンス**: 1名（マネージャー）
- **プロジェクトマネージャー**: 1名

#### 7.1.2 確保方法
- **内部リソース**: AI戦略担当、チェンジマネジメント、プロジェクトマネージャー
- **外部リソース**: 技術アーキテクト、データガバナンス（初期段階）
- **ハイブリッド**: 段階的な内部化を検討

### 7.2 成長段階の拡大

#### 7.2.1 拡大タイミング
- 導入後3-6ヶ月を目安
- 業務量・成果に基づいて判断

#### 7.2.2 拡大内容
- 技術アーキテクト: 1名追加
- チェンジマネジメント: 1名追加（スペシャリスト）
- AI戦略担当: 必要に応じて1名追加（アナリスト）

### 7.3 リソース確保の優先順位

#### 7.3.1 最優先
1. **プロジェクトマネージャー**: プロジェクト全体の管理
2. **技術アーキテクト（シニア）**: 技術標準の確立
3. **AI戦略担当**: 戦略の策定

#### 7.3.2 次優先
4. **チェンジマネジメント**: 全社的な推進
5. **データガバナンス**: セキュリティ・コンプライアンス
6. **技術アーキテクト（ミドル）**: 技術支援

### 7.4 スキル開発の推奨

#### 7.4.1 初期トレーニング
- 全員: AI・生成AIの基礎、Microsoft Copilotの基礎
- 技術アーキテクト: Microsoft 365、Azure、Copilotの技術的詳細
- データガバナンス: セキュリティ、コンプライアンス

#### 7.4.2 継続的な学習
- 月次学習会の実施
- 外部セミナー・カンファレンスへの参加
- 知識共有の仕組み構築

## 8. 結論・示唆

### 8.1 主要な発見

1. **初期段階は6名程度が適切**
   - 他社事例でも初期は6-10名程度
   - 段階的な拡大が効果的

2. **ハイブリッドアプローチが効果的**
   - 内部リソース + 外部リソースの組み合わせ
   - 段階的な内部化

3. **スキル開発が重要**
   - 内部リソースのスキル開発
   - 継続的な学習・向上

### 8.2 アイリスオーヤマへの推奨事項

1. **初期段階の体制**: 6名（内部 + 外部のハイブリッド）
2. **段階的な拡大**: 業務量・成果に基づいて拡大
3. **スキル開発**: 継続的なトレーニング・学習
4. **リソース確保の優先順位**: プロジェクトマネージャー、技術アーキテクト、AI戦略担当を最優先
