# P7 普及に向けて必要なアクション - アイリスがすべきこと（構造的整理）

## 1. 全体像：5つのカテゴリで整理

アイリスがAI普及を実現するために必要なアクションを、以下の5つのカテゴリで構造化：

  1. **戦略・目的（Why & What）** - 何を目指すか、なぜやるか
  2. **ガバナンス・リスク管理（Rules）** - 安心して使えるルール作り
  3. **環境・インフラ（Tools）** - 使いやすい環境整備
  4. **組織・人材・文化（People）** - 使いこなせる人と文化
  5. **プロセス・運用（Operation）** - 回し続ける仕組み

---

## 2. カテゴリ別：アイリスがすべきこと

### 2.1 戦略・目的（Why & What）

#### 2.1.1 目的の明確化（KGI/KPI設定）

**やるべきこと：**
- **方向性の決定**
  - 業務効率化（マイナスをゼロに）なのか、新規価値創出（ゼロをプラスに）なのかを明確化
  - アイリスの場合：P2の戦略に基づき、**「圧倒的なスピード」と「完璧な品質」の両立**を目指す
- **KGI/KPIの設定**
  - **利用率KPI**：現状20% → 3ヶ月で50% → 6ヶ月で70% → 12ヶ月で80%（他社事例ベース）
  - **時間削減KPI**：1人あたり月平均10-15時間の業務時間削減（デンソー事例：12時間/月を参考）
  - **業務効率化KPI**：主要業務で20-30%の時間削減
  - **部門別KPI**：各事業部で5-10件のユースケース創出（日立製作所：1,000件横展開を参考）

#### 2.1.2 適用領域の選定

**やるべきこと：**
- **段階的展開戦略の決定**
  - 全社一斉導入か、特定部署からのスモールスタートかを決定
  - **推奨**：スモールスタート（住友商事事例：50名→500名→9,000名の段階的展開を参考）
- **優先業務フローの選定**
  - **初期段階（0-6ヶ月）**：メール要約、会議要約、文書作成、プレゼン作成（技術検証結果より）
  - **発展段階（6-12ヶ月）**：SharePoint横断検索、部門特化AIエージェント（技術検証結果より）
  - 各事業部の特性に応じた優先順位付け

---

### 2.2 ガバナンス・リスク管理（Rules）

#### 2.2.1 利用ガイドラインの策定

**やるべきこと：**
- **入力データのルール明確化**
  - 個人情報、機密情報、顧客データの入力可否を明確化
  - 「入力してはいけないもの」をリスト化
  - **重要**：Microsoft 365環境内データは基本的に安全（技術検証結果より）
- **出力物の扱いルール**
  - 生成物の著作権、ファクトチェックの義務を明確化
  - 「AIの嘘」への責任の所在を明確化
  - **重要**：「AIのミスはプロセスの不備」と割り切る免責ルールの作成（P3の論点より）
- **禁止事項の明確化**
  - 競合他社への攻撃的な利用、差別的な生成などの禁止事項を明文化

#### 2.2.2 セキュリティポリシー

**やるべきこと：**
- **セキュリティ設定の確認・最適化**
  - Commercial Data Protectionの確認
  - DLP（Data Loss Prevention）ポリシーの設定
  - Azure ADによるアクセス制御の確認
  - **重要**：導入前に専門家による設定レビュー（技術検証結果より）
- **監査体制の構築**
  - ログの保存期間の決定
  - 監査ログの定期レビュー体制の構築
  - インシデント対応マニュアルの作成

---

### 2.3 環境・インフラ（Tools）

#### 2.3.1 ツールの選定・契約

**やるべきこと：**
- **基本ツールの選定**
  - **Microsoft Copilot for Microsoft 365**：全社的なAI民主化の基盤として導入（既にライセンス取得済み）
  - 自社の既存環境（Microsoft 365）との親和性を確認
- **発展段階ツールの検討**
  - **Copilot Studio**：部門特化AIエージェント構築用（6-12ヶ月後に検討）
  - **Azure AI Services**：高度なAI機能実装用（必要に応じて）

#### 2.3.2 インターフェースの整備

**やるべきこと：**
- **アクセス方法の統一**
  - Webブラウザ版、API連携、Slack/Teams連携Botなどの選択
  - **推奨**：Microsoft 365環境内での利用を基本とし、Teams連携を強化
- **アカウント管理**
  - SSO（シングルサインオン）連携の確認
  - 部署ごとの権限設定の設計

#### 2.3.3 既存システムとの連携

**やるべきこと：**
- **VBAマクロ資産の活用方針**
  - 既存VBAマクロ資産の棚卸し（重要度・使用頻度・置き換え可能性の評価）
  - 既存資産は維持しつつ、新規業務からCopilotを活用（技術検証結果より）
  - 役割分担の明確化：VBA（定型業務自動化）、Copilot（分析・文書作成）

---

### 2.4 組織・人材・文化（People）

#### 2.4.1 体制づくり

**やるべきこと：**
- **中央組織（CoE）の設置**
  - **推奨構成**：6-10名（日立製作所、パナソニック事例を参考）
    - AI戦略担当：1-2名（全社戦略・ロードマップ・予算への組み込み）
    - 技術アーキテクト：2-3名（技術設計、セキュリティ、ベンダー連携）
    - チェンジマネージャー：1-2名（教育プログラム、現場支援、事例集約）
    - データガバナンス担当：1名（ポリシー策定、コンプライアンス、リスク管理）
    - プロジェクトマネージャー：1名（進捗管理、KPI設定、ステークホルダー調整）
  - **役割**：戦略・ガバナンス・技術支援・標準化・知見共有（役割分担調査より）
- **事業部AI推進リーダー（Champion）の任命**
  - **推奨人数**：30-50名（部門別に1-3名、事務局リソース調査より）
  - **選定方法**：部門推薦＋自薦、AI活用に前向きな社員
  - **役割**：部門内での活用促進、質問対応、成功事例共有
  - **インセンティブ**：月額手当（1-3万円）、研修機会、社内表彰
- **経営層のコミットメント**
  - AI推進委員会の設置（委員長：取締役CTO、委員：各本部長）
  - 月1回の定例会議、予算確保、権限委譲

#### 2.4.2 教育・リテラシー向上

**やるべきこと：**
- **階層別研修プログラムの構築**
  - **経営層向け**：AI投資の意義、リスク、意思決定への活用
  - **一般社員向け**：プロンプトエンジニアリング基礎、ガイドライン周知（2時間eラーニング）
  - **推進者（Champion）向け**：高度な活用事例、他社事例の研究（8時間集中研修）
- **継続教育体制の構築**
  - **月次**：AI活用Tips配信、Q&Aセッション
  - **季度**：Advanced User Group会合、ベンダー最新情報
  - **年次**：AIサミット、外部講師招請、認定式
- **ナレッジシェアの仕組み**
  - 「すごいプロンプト集」や「成功事例」を共有するチャットチャンネルやWikiの用意
  - 定期的な勉強会やLT（ライトニングトーク）大会の開催
  - 全社的なAI活用コミュニティ（Teams等）の運営

#### 2.4.3 文化変革

**やるべきこと：**
- **「使わなければ損」という文化の醸成**
  - 成功体験の即時共有（社内SNS、メールマガジン）
  - 管理職の率先活用（トップダウン＋ボトムアップ）
- **失敗を恐れない文化の構築**
  - 「AIのミスはプロセスの不備」と割り切る免責ルールの徹底
  - 担当者を罰する文化の排除

---

### 2.5 プロセス・運用（Operation）

#### 2.5.1 フィードバックループ

**やるべきこと：**
- **不満吸い上げ窓口の設置**
  - 「使えない」「回答が微妙」といった不満を吸い上げる窓口の設置
  - 定期的なアンケート調査（月次）
  - フォーカスグループ、1on1インタビューの実施
- **利用状況のモニタリング**
  - Microsoft 365管理センターでの利用ログ分析
  - Dashboard機能を活用したKPI管理（技術検証結果より）
    - アクティブユーザー数、利用頻度、アプリケーション別利用状況
    - 部門別利用状況、ライセンス利用率
- **効果測定システムの構築**
  - BVA（Business Value Assessment）の活用
  - 特定業務の処理時間測定
  - ROI計算（月間削減時間×時給 - ライセンス費用）

#### 2.5.2 アップデート対応

**やるべきこと：**
- **定期的な見直しサイクルの設定**
  - AIモデルは進化が早いため、ガイドラインやツールを定期的に見直す
  - 四半期ごとのレビュー、年次での総括
- **新機能の情報収集・共有**
  - Microsoftの最新情報の継続的な確認
  - 新機能の社内共有、活用方法の検討

#### 2.5.3 成功事例の横展開

**やるべきこと：**
- **成功事例の収集・共有**
  - 事業部ごとの成功事例創出（日立製作所：1,000件横展開を参考）
  - 成功事例の社内ポータル、メールマガジン、イベントでの共有
- **表彰制度の構築**
  - 優秀活用部門・個人の表彰、社内報道
  - 「Copilotチャレンジカップ」などのコンペ開催（九電グループ事例を参考）

## 3. 実施優先順位（時系列）

### 3.1 導入前準備（-3ヶ月〜0ヶ月）

**最優先：**
1. **組織体制の構築**
   - 中央組織（CoE）の設置（6-10名）
   - 事業部AI推進リーダー（Champion）の選定・任命（30-50名）
   - 役割分担の明確化
2. **セキュリティ・ガバナンス**
   - セキュリティ設定の確認・最適化（専門家によるレビュー）
   - DLPポリシーの設定
   - 利用ガイドラインの策定
3. **戦略・KPI設定**
   - 目的の明確化（方向性の決定）
   - KGI/KPIの設定（利用率、時間削減、業務効率化）
   - 適用領域の選定（優先業務フローの決定）

**次優先：**
4. **教育プログラムの準備**
   - 階層別研修プログラムの開発
   - eラーニング、ワークショップの準備
5. **コミュニケーション体制の構築**
   - 定例会議の設定（中央組織と事業部AI推進リーダーの月次定例会）
   - 全社的なAI活用コミュニティ（Teams等）の構築

### 3.2 導入初期（0-3ヶ月）

**最優先：**
1. **Pilot導入**
   - 特定部門・ユーザーでのPilot導入（3-5部門、50-100名）
   - 優先ユースケースの展開（メール要約、会議要約、文書作成、プレゼン作成）
2. **利用状況のモニタリング開始**
   - Dashboard機能を活用したKPI管理
   - 利用ログ分析、アンケート調査
3. **課題対応**
   - 不満吸い上げ窓口の設置
   - 課題の収集・対応

**次優先：**
4. **成功事例の収集**
   - 事業部ごとの成功事例創出
   - 成功事例の共有（社内ポータル、メールマガジン）
5. **教育の実施**
   - 階層別研修の実施
   - ナレッジシェアの開始

### 3.3 拡大期（3-6ヶ月）

**最優先：**
1. **全社展開（段階的）**
   - 成功部門から順次展開（3ヶ月ごとに2-3部門）
   - 波状展開戦略の実施
2. **ユースケースの拡大**
   - Excel分析、メール横断検索の展開
   - 部門別ユースケースの開発
3. **効果測定・評価**
   - KPI達成状況の評価
   - ROI計算、効果の可視化

**次優先：**
4. **定着化施策の実施**
   - 表彰制度の構築・実施
   - 継続教育の強化
5. **改善サイクルの確立**
   - PDCAサイクルの確立
   - 継続的な改善

### 3.4 高度化期（6-12ヶ月）

**最優先：**
1. **高度なユースケースの展開**
   - Copilot Studioの検討・導入
   - SharePoint横断検索の展開
   - 部門特化AIエージェントの構築
2. **全社展開の完了**
   - 全部門での展開完了
   - 利用率80%達成

**次優先：**
3. **継続的な改善**
   - 定期的なKPI評価
   - 成功事例の横展開
   - 次年度計画の策定
